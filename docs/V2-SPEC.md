## 1. 比例尺：换成"线性真实距离"

旧公式 `orbit(au) = 34 + 15·au^0.62` 是径向压缩，会把椭圆压成非相似形。用户明确要求"改公式、更真实、空间更大"。

新法则（**距离是严格的相似变换**，轨道形状、倾角、相对间距 100% 保真）：

```
SCENE_AU = 60                      // 1 AU = 60 场景单位
orbitUnits(au)  = 60 * au          // 线性，无压缩、无偏移
bodyRadius(km)  = 1.3 * (km / 6371)^0.35
```

约束与实测（已用脚本核算过，见 `.data/scale-probe.py`，不要自行改常数）：

| 天体 | 距离(单位) | 视觉半径 |
|---|---|---|
| 太阳 | 0 | 6.72 |
| 水星 | 23.2 | 0.93 |
| 金星 | 43.4 | 1.28 |
| 地球 | 60.0 | 1.30 |
| 火星 | 91.4 | 1.04 |
| 木星 | 312.2 | 3.01 |
| 土星 | 572.2 | 2.82 |
| 天王星 | 1151.4 | 2.11 |
| 海王星 | 1804.2 | 2.09 |
| 冥王星 | 2368.8 | 0.72 |

- 水星在 3.5 个太阳半径处，所以**太阳辉光 scale 必须从 3.4 降到 ≤ 2.4**，否则辉光会吞掉水星轨道。
- 相机：`far` 提到 120000，`near` 保持 0.5，并开启 **`reversedDepthBuffer: true`**（WebGPURenderer 支持；`logarithmicDepthBuffer` 在 Renderer 里和 reversed 互斥会被自动关掉，别用）。不开的话 0.5~120000 的深度精度会 z-fighting。`maxDistance` 提到 40000。
- 默认 home 机位要能同时看到内行星带和木星，建议 `(0, 900, 1900)` 附近，你用截图定。
- `scale.orbit()` 现在被小行星带、轨道线、太阳半径等多处调用，改签名时全项目搜一遍。

**半径曲线改成 0.35 指数**后，木星/土星的视觉半径会小 10%，这是刻意的（真实比例下气态巨行星没那么夸张）。旧的三套 `SCALE_MODES`（visual/log/real）保留但改成新曲线，默认模式换成新的 `true` 模式。

### 保底可见性（必须做）

距离拉大 12 倍后，全景下水星只有 0.05 像素。给每个天体加一个**最小屏幕尺寸**：投影半径 < 1.2 px 时改画一个 2.6 px 的加色 billboard（颜色用 `body.color`），保证全景里能看到"那有个东西"。这不是装饰，是可用性。

## 2. 卫星：208 颗，真实轨道要素

数据已生成：`src/data/catalog/moons.json`（53 KB）。**不要改数据文件，也不要用程序随机生成卫星。**

```json
{"parent":"jupiter","name":"Io","nameZh":"木卫一","radiusKm":1818.1,"estimated":false,
 "aKm":421800.0,"e":0.004,"i":0.036,"node":43.9,"peri":84.1,"periodDays":1.769,
 "color":"#e8d17a","id":"jupiter-io"}
```

- 覆盖：地球 1、火星 2、木星 79、土星 81、天王星 27、海王星 13、冥王星 5。
- 全部有真实的 a/e/i/Ω/ω/周期/半径，来自 JPL/IAU 汇编；25 条缺 Ω/ω（值为 null，按 0 处理）。
- `i` 是**相对母星赤道面**的倾角，所以卫星必须挂在母星赤道面上（母星轴倾角要继承），逆行卫星 i>90°（共 119 颗）要自动反向公转。
- 相位（历元平近点角）没有公开数据：用 `hash(id)` 生成稳定的初始相位。地球的月球例外，保留现在那条真实平黄经公式。
- 半径：卫星尺寸必须**相对母星按真实比例压缩**，不能直接用行星半径曲线（否则火卫一只剩 0.003 单位，看不见）：

```
moonRadius(parentVisR, rKm, parentKm) = max(0.02, parentVisR * sqrt(max(rKm,0.05)/parentKm))
```
  例：月球 0.68、木卫一 0.49、木卫三 0.51、土卫六 0.47、火卫一 0.06。

- 轨道半径（真实 a/Rp 从 1.83 到 1965，跨三个数量级，必须压缩）：

```
f(x) = x <= 2.4 ? x : 2.4 * (x/2.4)^0.42          // x = aKm / parentKm
moonOrbit = parentVisR * min(f(x), 0.45 * gapToNeighbour / parentVisR)
```
  2.4 以内保持线性：土星的环卫星（Pan 2.29 Rp）、天王星的牧羊卫星（Cordelia 1.96 Rp）必须留在环里，这个次序不能破。
  上限 `0.45×邻星间距` 只对地球生效（月球 12.1 → 7.5 单位），否则月球轨道会比金星轨道还显眼。

### 性能与实现要求

- 208 颗卫星不能是 208 个独立 MeshMaterial。**按母星分组，用 `InstancedMesh`**（7 个 draw call），每帧在 CPU 上解 208 个开普勒方程（208 次/帧，可忽略）。
- `instanceColor` 用数据里的 `color`。
- 半径 ≥ 200 km 的 ~20 颗"大卫星"升档：被聚焦时换成独立球体 + **程序化 canvas 纹理**（512²，种子来自 `id`，按类别调色：冰卫偏白、岩卫偏灰、木卫一偏黄）。项目里没有这些卫星的真实贴图，程序化纹理要在 README 里如实标注。
- 标签：只在相机距母星 < 60 单位时显示该星系卫星名，且只显示 `radiusKm > 100` 的；全部显示会糊成一片。
