# Solar System · three.js WebGPU + TSL

[![Deploy to GitHub Pages](https://github.com/pearsnow/solar-system/actions/workflows/deploy.yml/badge.svg)](https://github.com/pearsnow/solar-system/actions/workflows/deploy.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

**在线预览 → https://pearsnow.github.io/solar-system/**

一个把精度拉到素材上限的太阳系，用 three.js r187 的 **WebGPU + TSL** 节点管线实现。

不是某个开源项目的复制，而是针对 8 GB 显存和「视觉优先」重新做的取舍：
真实 J2000 开普勒轨道、拆开的独立贴图、真法线、面向相机的大气辉光。

## 轨道精度

不是「看着差不多」。`tools/verify-orbits.mjs` 会把本地解算结果和
[JPL Horizons](https://ssd.jpl.nasa.gov/horizons/) 的官方星历逐点对比。

```powershell
npm.cmd run verify:orbits
```

```
body      date         |Δr| AU      |Δr| km        tol AU      result
mercury   2000-01-01     6.93e-6       1.04e+3      1.0e-4  PASS
venus     1969-07-20     5.26e-5       7.86e+3      1.1e-4  PASS
earth     2026-11-04     4.26e-5       6.37e+3      1.6e-4  PASS
mars      2049-12-31     4.63e-4       6.93e+4      5.3e-4  PASS
jupiter   2000-01-01     7.69e-3       1.15e+6      2.6e-2  PASS
saturn    2000-01-01     2.57e-2       3.85e+6      5.3e-2  PASS
uranus    2000-01-01     7.20e-3       1.08e+6      2.2e-2  PASS
neptune   2000-01-01     7.35e-3       1.10e+6      1.3e-2  PASS
```

**容差不是拍脑袋定的。** 用的是 JPL 官方随表发布的标称误差
（λ 弧秒 / ρ 千公里），换算成距离误差再乘 1.5 的余量。
外行星额外叠加 `1e-2 AU` —— 那是太阳绕太阳系质心的摆动幅度
（木星拉扯，最大约 0.0074 AU），解析表无法描述它，属于物理下限而非实现误差。

内行星误差量级 **1e-5 ~ 5e-4 AU**，这才是这套实现的真实水平。

Horizons 的返回结果会缓存到 `tools/fixtures/horizons.json`，之后离线可复现。
`--refresh` 强制重新拉取。冥王星的对照组还需要联网跑一次才能进缓存，在那之前它会显示
`SKIP (no fixture)` —— 跳过不等于通过，其余 8 颗行星的 32 个点仍然照常对拍。

> 本机 Node 的 `fetch` 连不上 `ssd.jpl.nasa.gov`（undici 连接超时），
> 脚本内置了 PowerShell 回退通道，只在 fetch 失败时启用。

## 比例：三条各自命名的谎

真实比例无法观看：海王星有 30 AU 远，木星直径是地球的 11 倍。任何太阳系可视化都要撒谎，
区别只在于**有没有把谎说出来**。默认模式 `true` 用了三条互不相同的映射，每一条都是刻意的：

| 量 | 映射 | 为什么这么做 |
|---|---|---|
| 距离 | `60 × au`（线性） | 换乘后再看开普勒第二定律，椭圆形状、倾角、各行星相对位置全都不用重算 |
| 天体半径 | `1.3 × (km/6371)^0.35` | 纯线性下地球是亚像素；幂律把 109 倍的真实差距压到 6.7 倍 |
| 卫星轨道 | `r ≤ 2.4 Rp ? r : 2.4 × (r/2.4)^0.42` | 只压缩外圈，2.4 倍行星半径以内原样保留 |

**距离必须是线性压缩，不能逐轴缩放。** 逐轴缩放会改变椭圆的长宽比，行星会偏离自己
被画出来的轨道线；径向压缩（只缩短位置向量、保留方向）能保证行星永远落在轨道上。
这也是 `?scale=visual` 与 `?scale=log` 只改变轨道半径、不改形状的原因。

**卫星压缩在 2.4 Rp 以内是恒等映射，这条不是凑出来的。** 土星环外缘在 2.42 Rp，
天王星环在 2.0 Rp 附近，如果对小半径也施加幂律，土卫十八（Pan，2.29 Rp）会被推到
3.47 Rp —— 五颗牧羊犬卫星会集体跑到环外面去。改成 2.4 Rp 以内不压缩之后，
环卫星重新回到环里。这个 bug 在 v2 开发中真实发生过一次，靠对比表抓回来的。

冥王星按瞬时轨道根数走椭圆解，远日点 49.56 AU = 2973 场景单位，是全场的边界。


### ⚠️ 源站的 `8k_` 前缀不可信

脚本会打印每张源图的**真实尺寸**，结果和文件名对不上：

| 文件名 | 实际分辨率 |
|---|---|
| `8k_earth_*.jpg` / `8k_mars.jpg` / `8k_mercury.jpg` | 8192×4096 ✅ |
| `8k_sun.jpg` / `8k_jupiter.jpg` / `8k_saturn.jpg` | **4096×2048** ❌ |
| `4k_venus_atmosphere.jpg` | 4096×2048 |
| `2k_uranus.jpg` / `2k_neptune.jpg` | 2048×1024（已是上限） |

所以 `bodies.js` 里的 `textureLevel` 按**实测**填，不是按文件名：
`8k` 只有水星、火星、地球；太阳、金星、木星、土星是 `4k`；天王星、海王星 `2k`。

**天王星和海王星没有更高分辨率可用。** JPL 自己的纹理库里这两颗都标注
`fictional`，天王星的原文是 "Plain solid blue texture. (It's just a solid color,
really!)" —— Voyager 2 只飞掠过一次，而天王星本身几乎没有表面特征。
用 2K 底图 + 极低幅度的程序化条带，比贴一张假的 8K 放大图诚实。

| 输出 | 来源 | 处理 |
|---|---|---|
| `earth/day.jpg` | `8k_earth_daymap.jpg` | sRGB，q92 4:4:4 |
| `earth/night.jpg` | `8k_earth_nightmap.jpg` | sRGB，q92 4:4:4 |
| `earth/normal.jpg` | `8k_earth_normal_map.tif` | 线性，q95 4:4:4 |
| `earth/clouds.jpg` | `8k_earth_clouds.jpg` | 转灰度，q90 |
| `earth/rough.jpg` | `8k_earth_specular_map.tif` | 反相（白=水 → 光滑） |
| `<body>/day.jpg` | `<body>` 源图 | sRGB，q92 4:4:4 |
| `sky/milkyway.jpg` | `8k_stars_milky_way.jpg` | 8192×4096 等距圆柱投影，q90 |

## 按需换档（LOD）

行星和月球启动时都是 **2K**，太阳直接加载允许的最高档位。行星和月球只有在相机靠近（< 8 个天体半径）时才升到该天体的原生档位，
离开（> 18 个天体半径）再降回去。两个阈值之间是滞回区，否则停在边界上的物体会每帧重建材质。

**阈值必须按半径算，不能按绝对距离算。** 第一版用了 25 个半径，结果聚焦地球时水星也被
升到了 8K —— 因为内行星彼此只隔几十个显示单位，而水星的半径只有 0.89，25 个半径才 22 个单位。
收紧到 8 之后，只有真正在镜头里的那颗会升档。

换档的实现是**重建实例**而不是替换贴图句柄。TextureNode 的运行时换绑在后端行为上不够确定，
重建虽然要重新编译一次着色器（几十毫秒），但只有一条代码路径，也不会留下着色器状态残留。

HUD 的「贴图上限」表示质量档位上限；信息面板的「贴图档位」表示天体当前实际档位。浏览器不提供 GPU 名称时显示「GPU 信息不可用」。

实测显存占用（HUD 实时显示）：

| 场景 | 贴图占用 |
|---|---|
| 全部按原生档位加载（不换档） | ≈ 1.27 GB |
| 全景视角（8 天体 2K + 太阳 4K） | **182 MB** |
| 聚焦木星（4K） | 204 MB |
| 聚焦地球（5 张 8K 贴图） | **986 MB** |

全景视角下省掉 86% 的显存，而那时候行星本来就只有几个像素。

## 三个关键实现

**1. 法线用真的，不用亮度假凸起**

官方示例为了省一张图，拿地表亮度当高度做 bump。这里用 r187 的 `normalMap`
节点配 8K 切空间法线，山脉和海岸线是真的。

**2. 大气辉光不能用球壳**

球壳的剪影在数学上必然是硬边圆环：球面在边缘处与视线平行，任何写在该半径上的
衰减都会被挤进不到一个像素。换成面向相机的四边形 + 线性半径，才有真正的柔边。

**3. 轨道压缩是径向的，不是逐轴缩放**

每个位置向量只压缩长度、保留方向。这样行星永远落在它被画出来的轨道线上，
代价是椭圆形状被扭曲。逐轴缩放会让行星偏离自己的轨道。

**4. 土星环的阴影是解析解，不是阴影贴图**

「环上一点朝太阳方向的射线与星球求交」，在着色器里直接解二次方程：

```
disc = (p·L)² − |p|² + 1        // 单位球
t    = −(p·L) − √disc           // 近交点
```

判别式趋零处就是阴影边缘，用 `smoothstep` 得到半影。为一个视觉细节开立方体阴影贴图
（点光源要六个 pass）不值得，而这个解法是精确的、零成本的。

**5. 环的径向坐标在着色器里算，不写进 UV 属性**

第一版把 `u = (r − inner)/span` 写进几何体的 UV 属性，环上出现一层细网格。
排查过程：贴图数据是平滑的、alpha 是平滑的、换成纯色输出网格就消失。
最后定位到顶点属性插值 —— 环的三角形非常细长，属性插值误差在被缩小采样后
变成了可见的栅格。改成每片元从 `positionLocal.xz` 直接算半径，问题消失。

太阳盘面以 0.25 混入白色，保留原有色调和临边昏暗。辉光基准为 2.4 倍太阳半径和 0.85 强度；相机距太阳中心从 15 降到 6 个太阳半径时，强度系数平滑降至 0.20。远景在 400–800 场景单位之间将辉光半径平滑扩大到 4.5 倍。

**6. 小行星带要两层，一层不够**

- `InstancedMesh` 岩石：2866 个 JPL SBDB 轨道各自推进，尺寸由目录直径映射。
- 半透明尘埃环：全景视角下岩石是亚像素的，没有这层带子会直接消失。

CPU 每帧更新六分之一的实例，以降低单帧计算量；小行星显示半径上限为 0.32，距离相机 14 到 2 个场景单位时平滑缩小，材质保持不透明。41 颗彗星使用从近日点传播的通用变量轨道（10 颗偏心率 ≥ 1，走双曲分支），选中时显示对应轨道线与信息面板；彗发和尘埃/离子两条尾巴的活动度在 1.5–6 AU 之间平滑减弱，取景距离按尾长的 2.4 倍计算并限制在 3–60 场景单位。相机跟随彗星时不会把取景距离锁死在选中那一刻：尾巴随日心距变长超过 25% 就重新取景，用户自己滚轮缩放则不干预。

行星小于屏幕投影阈值时显示 3.2 像素亮核和 7 像素柔光。行星的卫星面板优先显示半径最大的八颗，展开后按轨道半长轴排列全部卫星。

**7. 姿态和自转都由 IAU 的极轴与本初子午线驱动**

天体朝向分两层：`tilt` 节点用 IAU 北极方向（`pole: [RA, Dec]`）对齐自转轴，`globe` 的 `rotation.y`
让贴图的 0° 经线对准 IAU 本初子午线（`w0: [W at J2000, °/day]`）。两者都是纯几何量，
不靠"倾角 + 时长"凑——所以给定日期，哪条经线正对太阳是对的。

早期版本把所有倾角都写成 `tilt.rotation.z = 倾角`，等于把所有极轴压进 X-Y 平面。倾角**大小**对，
**方位角**丢了 68°～70°：地球的四季整体偏了约三个月（次太阳点纬度峰值落在 9 月底而非 6 月 21 日），
土星环在 2026 年 11 月被画成张开 29°，而真实值约 −6.5°。换成 IAU 极轴后，土星环面交叉日
（2025-03-23）算出来是 **+0.01°**，2032 年 −26.90°，与真实环面开合史吻合。

`rotationHours` 的符号不再参与渲染，逆行完全由 `w0` 的速率符号承担（金星 −1.48、天王星 −501.16 °/日，
冥王星速率是正的但极轴在南半天，转向同样正确）。`rotationHours` 只留给信息面板和自检。

每帧的相位差钳在 ±0.5 rad（约 60fps 下 4.8 转/秒）。1 小时/秒 到 1 天/秒 这几档相位差本来就在
0.27 rad 以内，走的是精确相位；到 1 年/秒 以上地球每帧要转 6 圈，钳位让它看起来是"快速自转"
而不是随机频闪——代价是高速档下角度会落后于日期，稳定后才与日期严格对应。

地球特写视图（`?earth`）没有模拟时钟，用一个视图私有的伪儒略日驱动，12 秒一圈；
系统视图里地球是 23.94 小时一圈，跟着时间条走。



## 已知取舍

### R1 比例与天体

默认 `true` 比例以 60 场景单位表示 1 AU，天体半径采用 0.35 幂律；卫星距离采用连续的分段幂律压缩。`?scale=visual`、`?scale=log` 和 `?scale=real` 保留原有公式。冥王星使用椭圆瞬时轨道根数和程序化心形亮区，默认尺度远日点约为 2973 场景单位。

卫星目录包含 210 颗（土星 82、木星 79、天王星 27、海王星 14、冥王星 5、火星 2、地球 1）：地球月球保留相对黄道的平黄经实现，其他卫星相对母星赤道排列。大卫星选中后使用程序化球面贴图。母星 LOD 换档时保留位置与倾角骨架，避免销毁卫星节点。

### R1 踩坑

太阳辉光缩至 2.4 倍半径，以减少对水星近日点的遮挡。渲染器请求反向深度；WebGL2 回退时相机远平面限制为 40000。HUD 显示实际渲染后端。卫星轨道是按目录参数和周期的可视化近似，拥挤的同轨卫星没有人为错位。

| 项目 | 处理 |
|---|---|
| 月球轨道半径 | 使用与其他卫星相同的分段压缩，并限制在相邻行星轨道间距的 45% 以内；倾角 5.145° 相对黄道 |
| 月球大小 | 不走行星的半径压缩曲线，按真实比例跟随地球，否则会被放大到地球的 43% |
| 地月质心 → 地球本体 | 未施加。偏移约 3.1e-5 AU，本尺度下是 0.0015 个显示单位，不可见 |
| 月球轨道 | 只用平均黄经，无摄动项。视觉正确，天文级别不够 |
| 土星环贴图 | 固定 2K。更高分辨率只会和各项异性过滤采样打架，产生拍频 |

### v2 的三处妥协
| 项目 | 处理 |
|---|---|
| 卫星贴图 | 只有月球、四颗伽利略卫星、土卫六等大卫星有程序化球面贴图，2 像素级的卫星直接用纯色球。真实影像拿不到，画质下限比行星低一档 |
| 彗星尾巴 | 不是粒子系统，是两张面向相机的加法混合贴图（离子尾冷蓝、尘埃尾暖白，差 0.12 rad）。真机上方向严格背离太阳，但靠近看能看出是平面 |
| 小行星尘埃环 | 全景下的那圈"带子"是程序化生成的半透明环，不是 2866 颗岩石。2866 颗在 2700 单位的取景距离上是亚像素的，没有这层带子整条小行星带会直接消失 |

### 程序化表面（v2 新增）
| 项目 | 处理 |
|---|---|
| 冥王星表面 | 隐式曲线画出的斯普特尼克平原"心形"亮区 + 克苏鲁暗区，全部在着色器里算。心形在球面上会随视角压缩变形，不是贴图 |
| 冥王星自转 | 6.4 天一圈。默认 1 天/秒时约 6 秒转过一整圈，所以心形是周期性转到正面来的，不是固定朝向 |
| 木卫一 / 欧罗巴 / 木卫三 / 土卫六等 | canvas 上三维值噪声生成，按天体调色：木卫一硫黄底 + 火山暗斑 + 极区暗化，欧罗巴白冰 + 褐色裂纹，木卫三暗高地 + 极冠 |

`tools/catalog/validate-catalogs.py` 的自检结果留在仓库里：木星 0.7%、土星 0.3%、
天王星 0.1%、海王星 0.2% 的母星质量偏差，说明卫星数据自洽；冥王星 13.4% 是真实的二体近似误差
（冥卫一质量占系统 12%）。

### 还没对上的天文细节

按可见程度排，这些是**明知不对但还没做**的：

| 项目 | 现状 | 真实 |
|---|---|---|
| 天王星 / 海王星的环 | 没有建模 | 天王星 13 条暗环、海王星 5 条 |
| 光照随距离衰减 | `PointLight` 衰减为 0，全系统照度相同 | 海王星只有地球的 1/904 |
| 太阳位置 | 固定在原点 | 绕太阳系质心摆动，木星+土星合成幅度约 0.0074 AU（0.44 场景单位） |
| 引力扰动 | 解析根数，无 N 体 | 有效区间约 1800–2050；木卫一/二/三的拉普拉斯共振、土卫六偏心率演化都没有 |
| 卫星轨道要素 | 25 颗近年发现的卫星缺升交点/近心点角距，按 0 处理 | 轨道面朝向未知 |
| 小天体 | 谷神星在表里但只当普通岩石（尺寸封顶 0.32）、无标签 | 还有阋神星、鸟神星、妊神星、赛德娜、木星特洛伊群、柯伊伯带 |
| 卫星数量 | 210 颗 | 已确认约 890 颗 |
| 食 / 凌日 | 无 | 月影投地、水星凌日、卫星互掩 |
| 大气 | 边缘辉光面片 | 真实散射，随视角和太阳高度变化 |
